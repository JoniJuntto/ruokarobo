# Campaign mode ("Isän joulu") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A finite, 8-chapter story mode for Ruokarobo, told over one Christmas Eve night, alongside the existing endless shifts.

**Architecture:** A `CHAPTERS` data table plus a `campaign` flag. When the flag is on, `setupLevel`/`startLevel`/`applyLevel` read the current chapter entry instead of deriving everything from the shift number. A new `'story'` state shows text cards between chapters. Three special mechanics sit on top: story orders that always go to the kids' home, collectible presents (ch 2) and the avanto rescue (ch 5).

**Tech Stack:** One file, `index.html` (inline ES module, Three.js r1xx from jsdelivr, PeerJS for online). No build step, no test framework. Served locally by `.claude/launch.json` → `python3 -m http.server 8765`.

**Spec:** `docs/superpowers/specs/2026-11-13-campaign-design.md`

## Global Constraints

- All code goes in `index.html`. No new files, no new dependencies.
- **Another change is in flight in `index.html`** (Santa's sleigh: `santa`, `updSanta`, `sleigh`, `SFX.jingle`). Start only after it is committed, and locate code **by function name**, never by line number.
- Endless mode must behave exactly as before when `campaign` is false (same quotas, hazards, orders, leaderboard, achievements).
- Story cards and chapter titles are English. Titles look like `LEVEL_NAMES`: `"Waking up (Herääminen)"`. Speech bubbles stay Finnish.
- The crash and the death are never shown. The robot never says it is dad.
- **Santa stays out of the campaign** (`santaIn = Infinity` when `campaign`): a sleigh knocking cars over on the night dad died in a car crash breaks the tone.
- S-1 is `robots[0]` (player 1 locally, the host online).
- PvP is off in the campaign. Campaign runs never call `recordRun()` or touch `best`.
- Save key: `localStorage['ruokarobo-story']` = `{ ch, money, up }`. Wrap every access in try/catch, like the existing `ruokarobo-best` code.

## Verification method

There is no test runner. Each task leaves **one console self-check** and **one browser check**:

- **Self-check:** a `storyCheck()` function in the module that `console.assert`s data invariants. It runs once at load. Any failure shows as `Assertion failed` in the console.
- **Browser check:** `preview_start {name: "ruokarobo"}`, then open `http://localhost:8765/?chapter=N`. The `?chapter=N` param (Task 1) starts the story directly at chapter N. Read the result with `get_page_text` / `read_console_messages`, and take a screenshot as proof.

## Review Focus

1. **Online guest joins mid-campaign.** The guest must see the same chapter, the cards, the presents and the kid. Covered in Task 2 (`levelMsg` carries `ch`) and Tasks 4–5 (snapshot fields).
2. **Robot breaks down while carrying Eetu or the sled.** That cargo must not be lost (`keep: true`), or the chapter can't be finished. Task 3/5 check.
3. **Battery runs out in any chapter.** *Try again* restarts the same chapter with the money and upgrades it started with, not shift 1. Task 1 check.
4. **Solo player in chapter 6 (tree) and chapter 5 (hook with no other robot).** Both must be finishable alone. Task 3/5 check.
5. **Teammate takes the sled by handoff.** Handoff to anyone but S-1 must be refused. Task 3 check.

### Task 3: Kids' home and story orders (gift, tree, sled)

**Files:** Modify `index.html`: `ORDERS`, `everyOrder`, `pickOrder`, the pickup/delivery block in the robot update (where `r.cargo = { dest, o, ... }` is set), the breakdown branch that does `r.cargo = null` ("Tilaus meni"), the handoff in `robotPairs`, and the house build (paper star in the `KIDS_HOME` window).

**Interfaces:**
- Consumes: `chap()`, `KIDS_HOME`.
- Produces: `ORDERS` entries 6–8, each with `story: true, home: true`:
  - `{ icon: '🎁', name: 'Present for the kids' }`

- [ ] **Step 1: Add asserts to `storyCheck()`:**
```js
console.assert(ORDERS.filter(o => !o.story).length === 6, 'endless order set unchanged');
console.assert(ORDERS.every(o => !o.story || o.home), 'story orders go home');
```
- [ ] **Step 2: Implement.**
  - **Endless mode:** `pickOrder` gives story orders weight 0, and `everyOrder` ignores them.
  - **Pickup:** a `home` order's `dest = KIDS_HOME`.
  - **Delivery:**
    - A duo order needs no helper when `campaign && robots.length === 1`.
    - Delivering the sled sets `goalDone = true`, plays `sfx('honk')` (*tö-tö-tööt*: three square beeps, the last one long; add it to `SFX`) and makes Eetu say "Isi tööttäs aina noin." at the door.
  - **Chapter 8 sled:** it is handed out only at the SALEPA door, only to `robots[0]`, and only once `delivered >= quota - 1`. Before that, ch 8 hands out gifts.
  - **Breakdown:** cargo with `keep` survives.
  - **Handoff:** cargo with `s1` never goes to a robot other than `robots[0]`.
- [ ] **Step 3: Verify.**
  - `?chapter=3`: every pickup is 🎁 and goes to the starred house.
  - `?chapter=6` solo: the tree crawls home and counts.
  - `?chapter=8`: after quota − 1 deliveries, S-1 gets 🛷 at Salepa. Delivering it plays the honk, shows Eetu's line and clears the chapter.
