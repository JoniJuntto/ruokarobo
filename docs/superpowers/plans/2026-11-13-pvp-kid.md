# PvP snowball kid Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** In PvP a player can switch from robot to a scoreless snowball kid on foot.

**Architecture:** The kid is an ordinary entry in `robots` with `r.kid = true`, so cameras, split screen, netcode, cars, plow and Santa keep working. `updRobot` branches early into a walking movement. `sync` hides the robot body and shows a `buildPerson` figure. Scoring code filters out kids.

**Tech Stack:** a single `index.html` (three.js, PeerJS). No test framework, so checks run in the browser via the dev page.

**Spec:** `docs/superpowers/specs/2026-11-13-pvp-kid-design.md`

## Global Constraints
- Kid only while `pvp`; the host clears `r.kid` whenever `!pvp`.
- The kid never counts in `ranked`, the winner or `pvpWin`.

## Review Focus
- An online guest switches to kid: the snapshot carries `kd`, and the guest's own view shows the person, not the robot.
- Every player is a kid: the end screen shows a tie and nothing crashes on an empty `ranked`.
- PvP is switched off on the title while someone is a kid: they become a robot again.
- A kid is hit by a car, the plow or Santa: it is knocked down, with no hp loss and no flying across the map.
- Pedestrians and NPC kids ignore the player kid.

### Task 1: kid entity, movement, toggle, look, scoring (all in `index.html`)
- [ ] Choosing: on the title in PvP, a rising edge of the snowball key (`inp.x`) toggles `r.kid` (in `updRobot`, host side). The `players` chips show 🧒, and a note explains the key.
- [ ] `updRobot`: after the hole and tow handling, `if (r.kid) return kidMove(r, inp, dt)`. Tank controls, about 3.4 rad/s turning at full rate, speed `KID_SP = 120` (reverse at half). Velocity decays while stunned. pushOut against SOLIDS and trees, clamp, snowball on X with `ballCd = .5`. No holes, orders, presents, boost, zap or hook.
- [ ] `damage(r)`: for a kid, `r.stun = max(r.stun, 2)` plus a shout, then return (no hp).
- [ ] `robotPairs`: a robot hitting a kid at a relative speed above 80 knocks the kid down.
- [ ] Snowball hits on a kid go through `damage` (already the case).
- [ ] Peds and NPC kids target `!r.kid`.
- [ ] `sync`: `r.body.visible = !r.kid`. Lazily build `r.person = buildPerson(r.mesh, r.color, '#fff', s)`, visible only for a kid. Walk swing, throw arm, fall over while `stun > 0`. No tracks, arrow or beam for a kid.
- [ ] Snapshot: `kd: r.kid` in `broadcast`, `kid: !!s.kd` in `applySnap`.
- [ ] `drawTag`: a kid gets a "❄️ Snowball kid / Pelt the robots" plate and no meters.
- [ ] Ranking: `ranked` and the pvp end-of-match sort use `robots.filter(r => !r.kid)`.
- [ ] Verify in the browser: two keyboard players, PvP on, Z toggles the kid, start, walk, throw, check the end screen.
- [ ] Commit.
